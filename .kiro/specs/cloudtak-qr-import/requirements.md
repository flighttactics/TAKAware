# Requirements Document

## Introduction

TAKAware currently supports scanning QR codes in iTAK comma-separated format and ATAK JSON format for TAK server certificate enrollment. CloudTAK (an open-source TAK server frontend) generates QR codes containing signed HTTPS URLs that point to downloadable .zip data packages. These data packages contain P12 client certificates, P12 truststores, and manifest/preference files with server connection details. This feature adds support for recognizing CloudTAK HTTPS URLs from scanned QR codes, downloading the referenced data package, importing the certificates, and auto-configuring the server connection.

## Glossary

- **QR_Code_Scanner**: The existing TAKAware component that captures QR code content from the device camera using CodeScannerView.
- **QR_Code_Parser**: The existing TAKAware parser (QRCodeParser) that interprets scanned QR code strings and produces CertificateEnrollmentParameters or triggers a data package import flow.
- **CloudTAK_URL**: An HTTPS URL generated by CloudTAK's Configuration Files page, containing a signed CloudFront download link for a .zip data package (e.g., `https://cloudfront-domain/path?Policy=...&Signature=...&Key-Pair-Id=...`).
- **Data_Package**: A .zip archive containing P12 certificate files, a P12 truststore, and a manifest.xml or .pref file describing server connection parameters.
- **Data_Package_Downloader**: A new component responsible for downloading a .zip data package from a CloudTAK_URL over HTTPS.
- **Data_Package_Parser**: The existing TAKDataPackageParser that extracts certificates and server preferences from a downloaded Data_Package.
- **Certificate_Manager**: The existing TAKAware component (CertificateManager) that imports X.509 certificates and identities into the iOS Keychain.
- **Settings_Store**: The existing TAKAware SettingsStore singleton that persists TAK server connection configuration (URL, port, protocol, certificates).
- **Cert_Enrollment_Screen**: The existing SwiftUI screen (CertEnrollmentScreen) where users scan QR codes and configure server connections.

## Requirements

### Requirement 1: Detect CloudTAK HTTPS URL in Scanned QR Code

**User Story:** As a TAKAware user, I want the QR code scanner to recognize CloudTAK signed URLs, so that I can connect to a CloudTAK server by scanning its configuration QR code.

#### Acceptance Criteria

1. WHEN a scanned QR code string starts with "https://", THE QR_Code_Parser SHALL identify the string as a CloudTAK_URL rather than returning wasInvalidString=true.
2. WHEN a scanned QR code string starts with "http://" (plaintext), THE QR_Code_Parser SHALL reject the URL and display an error indicating that only HTTPS URLs are accepted for security reasons.
3. WHEN a scanned QR code string has exactly 4 comma-separated values, THE QR_Code_Parser SHALL continue to parse the string as an iTAK QR code.
4. WHEN a scanned QR code string starts with "{", THE QR_Code_Parser SHALL continue to parse the string as an ATAK JSON QR code.
5. THE QR_Code_Parser SHALL validate that the detected URL is a well-formed URL before initiating a download.

### Requirement 2: Download Data Package from CloudTAK URL

**User Story:** As a TAKAware user, I want the app to download the data package from the CloudTAK signed URL, so that I can import server certificates without manual file transfer.

#### Acceptance Criteria

1. WHEN the QR_Code_Parser identifies a valid CloudTAK_URL, THE Data_Package_Downloader SHALL download the .zip file from the URL using HTTPS.
2. WHILE the Data_Package_Downloader is downloading, THE Cert_Enrollment_Screen SHALL display a progress indicator to the user.
3. WHEN the download completes successfully, THE Data_Package_Downloader SHALL save the .zip file to a temporary location accessible by the Data_Package_Parser.
4. IF the download fails due to a network error, THEN THE Data_Package_Downloader SHALL report a descriptive error message to the user.
5. IF the download fails due to an HTTP error status code, THEN THE Data_Package_Downloader SHALL report the HTTP status code and a descriptive error message to the user.
6. IF the downloaded file is not a valid .zip archive, THEN THE Data_Package_Downloader SHALL report an error indicating the file format is invalid.
7. IF the CloudTAK_URL signature has expired, THEN THE Data_Package_Downloader SHALL report an error indicating the URL has expired and the user should generate a new QR code.

### Requirement 3: Import Certificates from Downloaded Data Package

**User Story:** As a TAKAware user, I want the app to automatically import the P12 client certificate and truststore from the downloaded data package, so that I can establish a TLS connection to the CloudTAK server.

#### Acceptance Criteria

1. WHEN the Data_Package_Downloader saves a valid .zip file, THE Data_Package_Parser SHALL extract and parse the data package contents.
2. WHEN the Data_Package contains a P12 client certificate file, THE Data_Package_Parser SHALL import the client identity into the iOS Keychain via the existing certificate storage mechanism.
3. WHEN the Data_Package contains a P12 truststore file, THE Data_Package_Parser SHALL import the server trust certificates into the Settings_Store serverCertificateTruststore.
4. IF the Data_Package does not contain a P12 client certificate file, THEN THE Data_Package_Parser SHALL report an error indicating the client certificate is missing.
5. IF a P12 certificate file cannot be parsed, THEN THE Data_Package_Parser SHALL report a descriptive error identifying which certificate failed.

### Requirement 4: Extract Server Connection Details from Data Package

**User Story:** As a TAKAware user, I want the app to read the server connection details from the data package manifest, so that I do not have to manually enter the server host, port, and protocol.

#### Acceptance Criteria

1. WHEN the Data_Package contains a manifest.xml or .pref file, THE Data_Package_Parser SHALL extract the server URL, port, and protocol from the file.
2. WHEN server connection details are successfully extracted, THE Data_Package_Parser SHALL store the server URL in Settings_Store.takServerUrl.
3. WHEN server connection details are successfully extracted, THE Data_Package_Parser SHALL store the server port in Settings_Store.takServerPort.
4. WHEN server connection details are successfully extracted, THE Data_Package_Parser SHALL store the server protocol in Settings_Store.takServerProtocol.
5. IF the manifest or preference file is missing from the Data_Package, THEN THE Data_Package_Parser SHALL report an error indicating connection details could not be determined.
6. IF the manifest or preference file contains incomplete connection details, THEN THE Data_Package_Parser SHALL report an error specifying which fields are missing.

### Requirement 5: Auto-Configure and Trigger Server Connection

**User Story:** As a TAKAware user, I want the app to automatically configure and initiate a connection to the CloudTAK server after importing the data package, so that I can start using the TAK network with minimal manual steps.

#### Acceptance Criteria

1. WHEN all certificates and server connection details are successfully imported, THE Settings_Store SHALL set takServerChanged to true to trigger a reconnection.
2. WHEN the import completes successfully, THE Cert_Enrollment_Screen SHALL display a success message to the user.
3. WHEN the import completes successfully, THE Cert_Enrollment_Screen SHALL dismiss the enrollment flow and return the user to the connection status view.
4. IF any step of the import process fails, THEN THE Cert_Enrollment_Screen SHALL display the accumulated error messages to the user.
5. IF any step of the import process fails, THEN THE Cert_Enrollment_Screen SHALL allow the user to retry by scanning another QR code.

### Requirement 6: User Feedback During Import Process

**User Story:** As a TAKAware user, I want to see clear progress and status feedback during the CloudTAK data package download and import, so that I know what the app is doing and whether it succeeded.

#### Acceptance Criteria

1. WHILE the Data_Package_Downloader is downloading, THE Cert_Enrollment_Screen SHALL display a status message indicating the download is in progress.
2. WHILE the Data_Package_Parser is importing certificates, THE Cert_Enrollment_Screen SHALL display a status message indicating certificate import is in progress.
3. WHEN an error occurs at any stage, THE Cert_Enrollment_Screen SHALL display the error message within 1 second of the error occurring.
4. THE Cert_Enrollment_Screen SHALL prevent the user from initiating a second download while a download or import is already in progress.

### Requirement 7: Cleanup of Temporary Files

**User Story:** As a TAKAware user, I want the app to clean up temporary download files after import, so that the app does not accumulate unnecessary storage usage.

#### Acceptance Criteria

1. WHEN the data package import completes successfully, THE Data_Package_Downloader SHALL delete the temporary .zip file from local storage.
2. WHEN the data package import fails, THE Data_Package_Downloader SHALL delete the temporary .zip file from local storage.
3. IF the temporary file deletion fails, THEN THE Data_Package_Downloader SHALL log the failure without presenting an error to the user.

### Requirement 8: P12 Password Prompt

**User Story:** As a TAKAware user, I want the app to prompt me for the P12 password after scanning the QR code, so that the downloaded certificates can be decrypted and imported.

#### Acceptance Criteria

1. AFTER the QR_Code_Parser identifies a CloudTAK_URL and the user confirms the download (Requirement 9), THE Data_Package_Downloader SHALL download the .zip first, THEN THE Cert_Enrollment_Screen SHALL prompt the user to enter the P12 password before certificate import begins.
2. THE password prompt SHALL explain that this is the password set when generating the configuration file in CloudTAK.
3. THE password input field SHALL use a secure text entry (masked characters).
4. IF the user cancels the password prompt, THEN THE import flow SHALL be cancelled without downloading.
5. IF the P12 password is incorrect during certificate import, THEN THE Data_Package_Parser SHALL report a descriptive error and allow the user to re-enter the password without re-downloading the package.
6. THE P12 password SHALL NOT be persisted to UserDefaults, Keychain, or any other storage after the import completes.

### Requirement 9: URL Trust Verification

**User Story:** As a TAKAware user, I want the app to verify the download URL before fetching a data package, so that I am protected from malicious QR codes that could install rogue certificates.

#### Acceptance Criteria

1. WHEN the QR_Code_Parser identifies a CloudTAK_URL, THE Cert_Enrollment_Screen SHALL display the URL hostname to the user and ask for confirmation before downloading.
2. THE confirmation dialog SHALL clearly show the hostname being connected to (e.g., "Download configuration from cloudtak.example.com?").
3. IF the user declines the confirmation, THEN THE import flow SHALL be cancelled.
4. THE Data_Package_Downloader SHALL only accept HTTPS URLs — HTTP URLs SHALL be rejected with an error message.
5. THE Data_Package_Downloader SHALL enforce a maximum download size of 50 MB to prevent storage exhaustion.
6. THE Data_Package_Downloader SHALL enforce a download timeout of 60 seconds.

### Requirement 10: Zip Extraction Safety

**User Story:** As a developer, I want the zip extraction to be safe from path traversal attacks, so that a malicious data package cannot write files outside the designated temporary directory.

#### Acceptance Criteria

1. WHEN extracting files from the Data_Package, THE Data_Package_Parser SHALL validate that every extracted file path resolves within the designated temporary directory.
2. IF an extracted file path contains path traversal sequences (e.g., "../"), THEN THE Data_Package_Parser SHALL skip that entry and log a warning.
3. THE Data_Package_Parser SHALL reject zip entries with absolute paths.
4. THE Data_Package_Parser SHALL reject zip entries whose type is a symbolic link.
5. THE Data_Package_Parser SHALL enforce a maximum uncompressed output size of 250 MB and abort extraction if exceeded.
6. THE Data_Package_Parser SHALL enforce a maximum entry count of 1000 entries and abort extraction if exceeded.

### Requirement 11: HTTPS Redirect Safety

**User Story:** As a developer, I want the download to reject HTTP redirects, so that an attacker cannot downgrade the connection to plaintext.

#### Acceptance Criteria

1. THE Data_Package_Downloader SHALL implement a URLSession redirect delegate that inspects every redirect destination.
2. IF a redirect destination URL scheme is not "https", THEN THE Data_Package_Downloader SHALL abort the download and report an error.
3. HTTPS-to-HTTPS redirects SHALL be permitted.

### Requirement 12: P12 Password Memory Safety

**User Story:** As a developer, I want the P12 password to be handled securely in memory, so that it does not persist in heap after import.

#### Acceptance Criteria

1. THE P12 password SHALL be collected and passed to SecPKCS12Import as a Data buffer, not a Swift String, to allow explicit zeroing.
2. AFTER SecPKCS12Import completes (success or failure), THE import code SHALL zero the password Data buffer before releasing it.
3. THE P12 password SHALL NOT be stored in any @Published property, UserDefaults, Keychain, log output, or crash report.

### Requirement 13: Temp File Lifecycle

**User Story:** As a developer, I want the temp file lifecycle to be well-defined across password retries and edge cases, so that P12 material is never left on the filesystem.

#### Acceptance Criteria

1. THE Data_Package_Downloader SHALL write the downloaded .zip to a uniquely-named file in NSTemporaryDirectory().
2. WHILE the user is retrying the P12 password, THE temp .zip file SHALL be retained to avoid re-downloading.
3. WHEN the import succeeds, fails permanently, or is cancelled by the user, THE temp .zip file and extracted contents SHALL be deleted.
4. THE deletion SHALL be enforced via a defer block or equivalent cleanup mechanism to guarantee execution on all exit paths including crashes.
